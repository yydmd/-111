# 抢座速度升级：父会话参战 + 开火自动校准 + 自愈链路升级

## 依据（run #221/#230/#233/#235 遥测实证）
- 成功 100% 来自父会话完整解析链；racer 快捷路径 303 率 100%（token_age=0 排除 token 因素）
- 每次开抢后 ~1.5s 内平台对一切回 303（受理未开始），火力空打
- 串行兜底 0.3-0.6s 间隔是恢复链路最慢一环

## 改动（全部在 app/service.py 开抢路径 + db 的 app_settings 存储）

**1. 父会话参战（最大收益）**
- `_parallel_opening_shot`：poller 返回页面后，主线程 `_hold_until_fire` 对齐时刻，父会话直接用 poller 手头页面 `submit_once`（seats[0]，零额外取页），与 racer 并发
- 父会话结局汇入 outcomes（TOKEN_STALE 不计预算/SEAT_UNAVAILABLE 入 dead_seats/成功即 stop，全部走现有流程）
- 失败后串行轮换照旧，父会话这枪实质是"把已被验证的第一发提前"

**2. 开火时刻自动校准**
- 遥测记录每运行"首个非 TOKEN_STALE 响应"的服务器纪元 → offset = 该时刻 − fire_epoch
- app_settings 持久化 EMA（α=0.5，clamp [0,5]s，只记正偏移）
- `_scheduled_fire_epoch`：fire = 基准 + max(0, EMA − 0.2s 安全余量)；无样本时行为与现在一致
- 运行消息注明校准偏移与样本数，可人工审计

**3. 自愈末轮走完整解析链**
- race() 自愈循环：最后一轮（heals_used == RACER_HEAL_ATTEMPTS）跳过单 GET 快捷路径，直接 `resolve_submission_page` 完整链（遥测证明的 100% 成功路径）

**4. 串行兜底提速**
- RETRY_WAIT_RANGE (0.3, 0.6) → (0.2, 0.45)，保留随机抖动

**5. 遥测补强**
- 每次尝试 timing 增加 `at`（提交起发时的服务器纪元）；run 级记录受理时刻，支撑校准与后续调优
