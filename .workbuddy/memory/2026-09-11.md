## 找到的问题（按严重度，均有只读实证）

1. **【高】生产链路（browser 模式）让 service.py 的整条 HTTP 竞速/开火校准/时钟轮询成为死代码。**
   `enqueue_plan` 对非 probe 运行强制 `execution_mode="browser"`，`_add_login_columns`/`_apply_plan_data` 也把 `plan.execution_mode` 钉成 `browser`；`execute_plan` 在 `:1270` 直接 `_execute_browser(...); return`。
   因此 `:1417` 之后的 api 分支（`_scheduled_fire_epoch` / `_parallel_opening_shot` / `_poll_until_open` / `_await_fire_and_prefetch` / `_hold_until_fire` / `_load_fire_calibration` / `_record_accept_offset`）在生产永不执行。
   → `fire_accept_calibration` 只读不写、从不生效；README/problems.txt 描述的「父会话参战 / racer 错峰 / 303 自愈 / 迟到提交审计 / 开火校准」都不在现役链路上；`tests/upgrade_check.py` 43 项与 test_core 的 `_make_plan(execution_mode="api")` 都在验证死路径。

2. **【中高】`READ_SEAT_PATHS` 白名单与官方选座页真实流量相反。**
   项目自己的文档（`data/qa/upgrade-plan.md:404`、记忆 09-10）写明官方页面只调 `data/apps/seat/getdrawseat` 与 `data/apps/seat/seatgrid/roomid`（页面靠 seatgrid 判断格子已占）。
   实测（构造 RequestGate）：`getdrawseat` **拦截**、`seatgrid/roomid` **拦截**、`/data/apps/seat/index` **放行**（页面从不调它）。
   目前靠 SSR 内联 Vue 状态侥幸可用；一旦流程需要客户端刷新（或某校页面必须靠该 XHR）就会在 `prepare()` 处失败或看到过期的禁用态。

3. **【中】`web._next_run_at` 在 run_time ∈ 00:00–00:09 的预热窗口内把「下次执行」多算一天。**
   实测：run_time=00:05，现在 2026-09-03 23:56 → 返回 `2026-09-05T00:05`，真实下一次是 `2026-09-04T00:05`。根因：`awaiting_current_opening` 用「今天的 run_time」算 opening，跨午夜的预热窗口永不匹配，于是回落到 cron 的次日 occurrence 再 +LEAD。前端 `nextTargetDate = next_run_at + day_offset` 同样错一天。前端自带的 `nextRunCN` 已是死代码。

4. **【中低】时钟探测失败后 60s 重试会在开抢等待循环里同步阻塞。**
   `server_now()` → `server_offset()` 在 stale 时同步 `refresh()`（预算 4s，dense 8s，最多 6/16 次探测）。浏览器路径在 `while clock.server_now() < fire_epoch` 的 250ms 循环里高频调用它；一次网络故障后 TTL 降为 60s，正好可能在开抢窗内触发一次阻塞探测。

5. **【低】`security.redact` 过度改写（problems.txt 已记录，本轮补更强证据）。**
   `'选座参数 roomId=10713&enc=deadbeef&token=zzz'` → `'...&enc=<redacted>'`（`deadbeef&token=zzz` 被整段吃掉，因为 `[^,\s}"']+` 不含 `&`）；`{"fidEnc": "abc123"}` → 被 redact（fidEnc 不是密钥）。
   连带：`_execute_browser.checkpoint` 的 `changed` 用「已 redact 的 run.message」比「原始 message」→ 含此类 token 时每次都判定 changed，2 秒节流失效（每次 checkpoint 都 commit）。

6. **【低】通知设置：已存密钥无法解密时报 500。**
   实测 `unprotect_secret('dpapi:v1:<垃圾>')` 抛 `OSError [WinError 87]`；`notify.save_settings` 与 `web.put_settings` 只捕获 `ValueError` → FastAPI 500，而不是友好提示。

7. **【低】`tests/upgrade_check.py` 把临时库永久留在 `data/` 下。**
   每个场景 `data/uc-<name><时间戳>/check.db`，跑完不清理；本次一次运行新增 8 个目录（如 `uc-clamp-17890824400`），`data/` 已累积 40+ 个 `uc-*` 目录。

8. **【低/防御】** `single_instance.acquire_service_mutex` / `watchdog.acquire_watchdog_mutex` 的 `CreateMutexW` 未声明 `restype=wintypes.HANDLE`，且用 `GetLastError()`（未开 `use_last_error=True`）判断 `ERROR_ALREADY_EXISTS`；64 位下 HANDLE 被截成 c_int，单实例保证依赖这个脆弱读法。
9. **【低】** `browser_sessions.close_account` 只是把 `close_context` 塞进队列——线程已退出（`stopping`）时该任务永不执行。
10. **【低】** `service._run_snapshot:148` 硬编码 `600`（等于 `scheduler.LEAD_SECONDS`），两处若不同步会导致跨日 opening 判断错位；`web._next_run_at` 只看 `plan.enabled` 不看 `account.enabled`，账号停用时会显示「已启用 / 暂无已排定任务」。
